# Task 7: Code Audit

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-reviewing` — [skills/code-reviewing/SKILL.md](~/.claude/skills/code-reviewing/SKILL.md)

## Description

Full-feature code-quality audit of the JSON-API-scraper rewrite (Tasks 1–6).
Unlike the per-task reviewers (who looked at one file in isolation), this audit
reads **all** source files the feature created or modified and reviews them
**holistically** — looking for cross-component issues that only surface when the
pieces are seen together: who really owns the cookie store, whether the
API→WebView fallback is wired correctly end to end, whether concurrency
(`@MainActor` / `Sendable`) is sound across the async hops, and whether naming
and structure stay consistent with the existing codebase (AppKit-only,
ephemeral WebView, `AppLog` facade, strict Swift 6 concurrency).

This is **analysis only** — the auditor does not modify code. The deliverable is
an audit report (returned as the agent's final message, plus the per-finding
JSON sink described below). If issues are found, the feature lead spawns a
fixer; this auditor then becomes the reviewer for that fix. Because this task
produces a report and changes no code, there is **no TDD anchor** and **no
downstream reviewers**.

## What to do

- Load the `code-reviewing` skill and apply its review dimensions across the
  whole feature, not file by file.
- Read every source file created/modified in Tasks 1–6 (see Context Files) plus
  the tech-spec and decisions log so the audit is judged against the agreed
  design, not personal preference.
- Audit the cross-component concerns specific to this feature:
  - **Single source of truth for cookies (Decision 2):** confirm
    `WKWebsiteDataStore.default().httpCookieStore` is the only cookie jar; the
    API `URLSession` must run with no jar of its own
    (`httpCookieAcceptPolicy = .never`, `httpShouldSetCookies = false`,
    `httpCookieStorage = nil`); cookies are re-read each fetch and `Set-Cookie`
    is written back. Flag any drift or duplicated cookie state.
  - **Host scoping:** only `claude.ai`-domain cookies are attached, and the
    `Cookie` header is stripped on an off-host redirect.
  - **Fallback correctness (Decisions 4 & 7):** `.needsCookieRefresh` /
    `.decodeFailed` route to the WebView/DOM-scrape path; `.notLoggedIn` applies
    the backoff (no per-tick WebView spin-up) and the flag is cleared on
    wake/window-open. A 200 login-page body must classify as `.notLoggedIn`,
    not `.decodeFailed`.
  - **Concurrency:** `@MainActor` isolation for cookie reads and WebView use is
    correct; cross-actor hops are explicit; types crossing actor boundaries are
    `Sendable`; no data races under Swift 6 strict concurrency.
  - **Error handling:** every `UsageFetchResult` case is produced and consumed;
    `transport(Error)` does not silently blank `AppState`.
  - **Naming / structure consistency:** matches existing Scraper conventions
    (file naming, `AppLog` usage, no `NSLog`, ephemeral-WebView contract intact,
    AppKit-only).
- Classify each finding by severity (`critical` / `high` / `medium` / `low`),
  state the concrete issue with file + symbol references, and propose a fix.
- Write the report to the JSON sink path (see Reviewers) and return a concise
  summary as the final message. Do **not** edit any source file.

## Details

**Files:** none modified — analysis only. The audit produces a report, not code
changes.

**Dependencies:** Task 6 (and transitively Tasks 1–5) must be complete; this is
the Audit Wave (wave 5) and runs after all implementation. If a feature source
file listed above does not yet exist when the audit runs, note it as a gap
rather than assuming it was deleted.

**What to look for (cross-component, holistic):**
- Cookie ownership: the API `URLSession` must own no cookie jar; the WebView
  store is the single source of truth, re-read every fetch, with `Set-Cookie`
  written back. Watch for any independent jar, retained cookies, or stale
  copies that could drift from the login window.
- Host scoping: cookies attached only to `claude.ai`; `Cookie` header stripped
  on off-host redirect (redirect delegate).
- Fallback wiring: trace each `UsageFetchResult` case from `UsageAPIClient`
  through `QuotaScraper.scrape()` to its handling — `.needsCookieRefresh` and
  `.decodeFailed` → WebView path; `.notLoggedIn` → backoff (no per-tick WebView)
  cleared on wake/window-open; `.transport` → does not blank `AppState`.
- Classification order: a 200 whose body is the login page must resolve to
  `.notLoggedIn` before any JSON decode is attempted.
- Concurrency: `@MainActor` cookie reads before building the off-main request;
  explicit cross-actor hops; `Sendable` for boundary-crossing types; no races
  under Swift 6 strict concurrency + the upcoming features in Package.swift.
- Ephemeral-WebView contract preserved (AGENTS.md hard rule): no persistent
  WebView introduced on the normal API path.
- `AppLog` usage only (no `NSLog`); naming/file structure matches the existing
  `Scraper/` conventions.

**Edge cases to probe in the review:**
- Multiple orgs returned by `/organizations` — correct uuid chosen and cached
  (OrgIDStore), invalidated on auth/not-found failure.
- Empty `limits[]` with no flat fields → `.decodeFailed` (not a silent blank).
- `__cf_bm` rotation write-back keeps the shared store fresh.

**Implementation hints:** Judge against the tech-spec decisions and AGENTS.md
hard rules, not personal style. Keep findings concrete (file + symbol + why),
each with a severity and a proposed fix, so the feature lead can spawn a fixer
and you can re-review the fix. Secret handling (cookie logging, leakage) is
owned by Task 8 (Security Audit) — note it if seen, but do not duplicate that
audit's scope.
