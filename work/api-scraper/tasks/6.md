# Task 6: QuotaScraper orchestration (API-first, WebView fallback, backoff)

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Today `QuotaScraper` instantiates an ephemeral `WKWebView` on **every** 60 s
tick, loads `claude.ai/settings/usage`, waits for the React SPA, DOM-scrapes
via injected JS, parses with `QuotaParser`, then tears the WebView down. That
spawns WebContent/GPU/Networking helper processes each minute and keeps idle
RSS around ~82 MB.

This task makes `QuotaScraper` an **orchestrator**. On each tick it must call
`UsageAPIClient` (Task 5) FIRST and, on success, update `AppState.usage`
**without instantiating any `WKWebView`** — that is where the memory win comes
from. The existing WebView load → extract → parse → teardown pipeline is
**retained intact** and demoted to a fallback that only runs when the API path
cannot answer:

- `.success(usage)` → set `AppState.usage`, no WebView. (tech-spec "Normal tick")
- `.needsCookieRefresh` / `.decodeFailed` → fall through to the existing
  ephemeral WebView path (refresh Cloudflare cookies, surface login, DOM-scrape
  as last resort). (tech-spec "Fallback tick", Decision 3 + Decision 4)
- `.notLoggedIn` → apply **Decision 7 backoff**: set a "logged-out" flag that
  SUPPRESSES the WebView fallback on subsequent ticks (no login-WebView spam,
  preserves US-5 quiet-when-logged-out). Clear the flag on system wake and when
  the usage window opens, then re-probe the API.
- `.transport(error)` → log value-free (Decision 6), leave `AppState` unchanged,
  retry next tick (treat as a transient miss; do NOT enter the WebView path).

Timer (60 s + 10 s tolerance), watchdog, wake-observer, retry semantics, and
`AppState` wiring are all preserved. The DOM-scrape pipeline
(`QuotaScraper+JS/Extract/Navigation`, `QuotaParser`, `QuotaPayload`) is NOT
deleted — it is the last-resort fallback (Decision 4).

This is a cohesive single-method rewrite of the scrape entry point: keep the
fallback working at every step. Depends on Task 5 (`UsageAPIClient` +
`UsageFetchResult`).

## What to do

1. In `QuotaScraper.swift`, hold a `UsageAPIClient` instance (injectable for
   tests — see TDD anchor) and a `loggedOut: Bool` backoff flag, plus an
   `isFetching` guard.

2. Split the current WebView entry logic. The existing `scrape()` body (the
   `guard webView == nil` + `WebViewFactory.make` + load + `armWatchdog`)
   becomes a private `runWebViewFallback()`. The public tick entry stays named
   `scrape()` but becomes the API-first orchestrator, so the existing callers
   (timer in `start`, wake observer, `StatusBarController+Menu.openWindow`
   line 41) keep compiling.

3. In the orchestrator `scrape()`:
   - If `loggedOut` is set, do nothing this tick (suppress the fallback). Only
     wake / window-open clear it (step 6).
   - Guard `isFetching` so only one tick is in flight at a time.
   - Call `usageAPIClient.fetch()` (async, off-main per Task 5).
   - Apply the result back on MainActor and branch:
     - `.success(usage)` → `appStateRef()?.usage = usage`; clear `loggedOut`;
       reset `retryCount`. NO WebView.
     - `.needsCookieRefresh` / `.decodeFailed` → call `runWebViewFallback()`.
     - `.notLoggedIn` → set `loggedOut = true`; log a value-free notice; do NOT
       enter the WebView path.
     - `.transport` → log value-free; leave `AppState`; do not enter WebView.

4. Preserve the WebView fallback path unchanged in behavior: `runWebViewFallback()`
   still guards `webView == nil`, builds via `WebViewFactory.make(blockHeavy:)`,
   sets the navigation delegate, loads `usageURL`, arms the watchdog. The
   Navigation/Extract extensions, `QuotaParser`, `QuotaPayload`, watchdog,
   teardown, and `handleFailure` retry logic stay as-is. The existing `/login`
   detection in `QuotaScraper+Navigation.swift` should also set `loggedOut = true`
   (so a fallback that lands on the login page also backs off subsequent ticks),
   then tear down as it does now.

5. Concurrency: the class is `@MainActor`; `fetch()` runs off-main and its
   result is applied on MainActor (`AppState` is `@MainActor`). The `isFetching`
   guard prevents overlapping timer/wake/window-open triggers from stacking.

6. Decision 7 clear-points:
   - `observeWake()` handler: before forcing a scrape, set `loggedOut = false`
     so wake re-probes the API.
   - Window-open path: `StatusBarController+Menu.openWindow` calls
     `scraper.scrape()` (line 41). Add a public `clearBackoff()` that resets
     `loggedOut`, and call it before `scrape()` at that site so opening the
     usage window re-probes the API even while logged out.

7. Logging (Decision 6): every new log line is value-free — result case name,
   status-like events only. Never log cookie values, headers, or tokens.

## Acceptance Criteria

- [ ] `scrape()` calls `UsageAPIClient.fetch()` first; on `.success` it sets
      `AppState.usage` and instantiates NO `WKWebView`.
- [ ] `.needsCookieRefresh` and `.decodeFailed` fall through to the existing
      ephemeral WebView path (cookie refresh + DOM-scrape last resort).
- [ ] `.notLoggedIn` sets a backoff flag that suppresses the WebView fallback on
      subsequent ticks; the flag is cleared on system wake and on usage-window
      open, each of which re-probes the API.
- [ ] `.transport` errors leave `AppState` unchanged and do not enter the
      WebView path; logged value-free.
- [ ] Timer (60 s + 10 s tolerance), watchdog, wake-observer, and retry
      semantics are preserved; only one tick in flight at a time.
- [ ] The DOM-scrape pipeline (`QuotaScraper+JS/Extract/Navigation`,
      `QuotaParser`, `QuotaPayload`) is retained and still functions on fallback.
- [ ] No cookie value, header, or token is ever logged (Decision 6).
- [ ] New orchestration tests green; all existing tests still pass; `make ci`
      clean (build, tests, lint, format, dead-code).

## Details

<!-- All details for task execution -->

**Files:**
- `QuotaScraper.swift` — currently: `@MainActor final class QuotaScraper` with
  `scrape()` (lines 77-86) that guards `webView == nil`, builds an ephemeral
  WebView via `WebViewFactory.make(blockHeavy: true)`, loads `usageURL`, arms
  the watchdog. `start(appState:)` runs the first scrape, schedules the 60 s
  timer (`tolerance = 10`), and calls `observeWake()`. `observeWake()` forces a
  scrape on `NSWorkspace.didWakeNotification`. Change: add a `UsageAPIClient`
  member (injectable) + `loggedOut` flag + `isFetching` guard; make `scrape()`
  the API-first orchestrator; extract the WebView body into a private
  `runWebViewFallback()`; clear `loggedOut` in the wake handler before forcing a
  scrape; add a `clearBackoff()` for the window-open path.
- `QuotaScraper+Lifecycle.swift` — `armWatchdog`, `tearDown`, `handleFailure`
  (retry-once), `finishScrape`, `currentWebView`. Keep all; they belong to the
  fallback path. `handleFailure`/`finishScrape` still reset `retryCount`.
- `QuotaScraper+Navigation.swift` — read; on `/login` it logs "Auth required"
  and tears down (lines 14-18). Add: set `loggedOut = true` there so a fallback
  that lands on login also backs off subsequent ticks.
- `QuotaScraper+Extract.swift` — read; DOM-scrape success sets
  `appStateRef()?.usage = parsed` then `finishScrape()`. Unchanged.
- `StatusBarController+Menu.swift` — `openWindow()` calls `scraper.scrape()`
  (line 41). Add `scraper.clearBackoff()` immediately before that call so
  opening the usage window re-probes the API even while logged out.

**Dependencies:** Task 5 (`UsageAPIClient.fetch()` returning `UsageFetchResult`
with cases `.success`, `.needsCookieRefresh`, `.notLoggedIn`, `.decodeFailed`,
`.transport`). Match the exact API surface Task 5 ships (protocol vs concrete
type; async signature). No new packages.

**Edge cases:**
- Overlapping triggers (timer tick + wake + window-open close together): the
  `isFetching` guard makes later triggers no-ops until the in-flight fetch
  resolves.
- A `.notLoggedIn` arriving while a WebView fallback is mid-flight: set the flag
  but don't tear a healthy in-flight fallback prematurely — let the existing
  watchdog/teardown govern the WebView; the flag governs the NEXT tick.
- Clearing must happen BEFORE the fetch on wake/window-open, otherwise the
  orchestrator returns early and never re-probes.
- Async result applied on MainActor (`AppState` is `@MainActor`).

**Implementation hints:**
- Inject the API client so tests can substitute a stub returning scripted
  `UsageFetchResult`s and counting WebView instantiations. A protocol seam or an
  init parameter defaulting to the real client both work — follow Task 5.
- For the "no WebView instantiated" assertion, expose an observable the test can
  read: the existing `webView` property is accessible (`scraper.webView == nil`
  after a `.success` tick), or add a debug instantiation counter incremented in
  `runWebViewFallback()`.
- Keep the `usageURL`, `interval`, `watchdogTimeout`, `pollInterval`,
  `maxExtractAttempts`, `maxRetries` constants unchanged.
- Do not log cookie/header/token values anywhere in the new code (Decision 6) —
  log only result-case names and status-like events.
