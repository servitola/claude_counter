# Task 3: OrgIDStore (org uuid cache)

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

`UsageAPIClient` (Task 5) needs the claude.ai organization UUID to build the
`/organizations/{uuid}/usage` request. Discovering it requires an extra
`GET /api/organizations` round-trip. Doing that on every 60 s tick is wasteful,
so we cache the discovered UUID in `UserDefaults` and only re-discover when it
is missing or when a request fails with auth/not-found.

This task delivers a tiny, pure-Foundation `OrgIDStore` type with three
operations — read the cached UUID, write a freshly discovered one, invalidate
(clear) it. The store is the sole owner of the "Org UUID cache" shared resource
listed in the tech-spec's Shared Resources table.

Critically, the store must accept an **injected `UserDefaults`** (defaulting to
`.standard`) so unit tests run against an isolated `UserDefaults(suiteName:)`
and never read or mutate the app's real shared defaults. The tech-spec testing
strategy calls this out explicitly: "run against an isolated
`UserDefaults(suiteName:)`, not `.standard`, to avoid shared-state bleed
between tests."

## What to do

- Create `App/Sources/ClaudeCounter/Scraper/OrgIDStore.swift`.
- Define an `OrgIDStore` that wraps a `UserDefaults` instance, stored under a
  single well-known string key (e.g. `"org.uuid"` namespaced to the app).
- Provide three operations:
  - read the currently cached org UUID (returns optional — nil when absent),
  - write/store a discovered org UUID,
  - invalidate (remove) the cached UUID.
- Initializer takes a `UserDefaults` parameter defaulting to `.standard`, so
  production uses shared defaults and tests inject an isolated suite.
- Match the project's existing conventions: a small doc comment on the type
  (see `QuotaParser.swift` for the house style), `Sendable`/concurrency
  posture consistent with the strict-concurrency build (warnings-as-errors,
  `StrictConcurrency` is on — see `App/Package.swift`).

## TDD Anchor

Tests live in the existing `ClaudeCounterTests` target and use the **Swift
Testing** framework (`import Testing`, `@Test`, `#expect`) — match
`QuotaParserTests.swift`. Each test constructs the store with its own isolated
`UserDefaults(suiteName:)` (unique suite name per test, removed after use).

- `App/Tests/ClaudeCounterTests/OrgIDStoreTests.swift::writeThenReadReturnsUUID`
  — store a UUID, read it back, assert it equals what was written.
- `App/Tests/ClaudeCounterTests/OrgIDStoreTests.swift::invalidateClearsUUID`
  — store a UUID, invalidate, assert read returns nil.
- `App/Tests/ClaudeCounterTests/OrgIDStoreTests.swift::usesInjectedSuiteNotStandard`
  — write through a store backed by an isolated suite; assert
  `UserDefaults.standard` has no value under the key (no bleed into shared
  state).

## Details

**Files:**
- `App/Sources/ClaudeCounter/Scraper/OrgIDStore.swift` (new) — the cache type.
- `App/Tests/ClaudeCounterTests/OrgIDStoreTests.swift` (new) — unit tests.

**Dependencies:** None on other tasks (Wave 1, independent). Foundation only —
no new packages. `UsageAPIClient` (Task 5) will consume this store but is not
required to exist for this task.

**Edge cases:**
- Reading when nothing has been cached → returns nil (not a crash, not empty
  string).
- Invalidating when nothing is cached → no-op, no crash.
- Overwriting an existing UUID → new value replaces old on next read.
- Tests must use a unique suite name each run and clean it up (e.g.
  `removePersistentDomain(forName:)`) so suites don't accumulate or collide.

**Implementation hints:**
- Keep it a small `struct`/`final class` with a stored `UserDefaults` and a
  private constant key string. No singleton — the instance is created and
  injected by the caller (`UsageAPIClient`).
- Respect strict concurrency: `UserDefaults` is thread-safe; make the type
  `Sendable` if the build requires it. Follow the warnings-as-errors posture in
  `App/Package.swift` — a warning fails the build.
- Doc-comment the type briefly, matching `QuotaParser.swift` style.
- Do not log the UUID at info level on every read; if you log at all, keep it
  to discovery/invalidation events (consistent with Decision 6's "value-free
  events" spirit).
