# Task 5: UsageAPIClient (URLSession fetch + discovery + classification)

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Add `UsageAPIClient` — the networking core of the JSON-API scraper. It owns a
single `URLSession` and is responsible for turning "we have claude.ai cookies in
the WebView store" into a typed `UsageFetchResult` (`ClaudeUsage` on success, a
classified failure otherwise). This is the component that replaces the per-minute
WKWebView DOM scrape on the normal path.

Two load-bearing facts from the spike shape this task:
1. `GET https://claude.ai/api/organizations/{uuid}/usage` returns exactly the data
   the app needs as JSON, including ISO-8601 reset timestamps in `limits[]`.
2. **curl gets 403 (Cloudflare challenge); `URLSession` gets 200** with the same
   cookies + Safari UA, because Cloudflare gates on the TLS/JA3 fingerprint and
   Apple's networking stack matches what `cf_clearance` was issued against. This
   is why the fetch MUST go through `URLSession` and the smoke check MUST NOT use
   curl.

The client must reuse the cookies stored in `WKWebsiteDataStore.default()` without
keeping a cookie jar of its own (Decision 2): the `URLSession` is configured with
`httpCookieStorage = nil`, `httpCookieAcceptPolicy = .never`,
`httpShouldSetCookies = false`, and a redirect delegate that strips the `Cookie`
header the moment a redirect leaves `claude.ai`. The WebView store is the single
source of truth, re-read each fetch via `CookieBridge` (Task 4).

Flow per fetch: discover the org uuid (cached in `OrgIDStore` from Task 3; on a
miss, `GET /api/organizations` and pick the active/first uuid), then
`GET /api/organizations/{uuid}/usage` with the Safari `customUserAgent` (reuse the
exact UA string `WebViewFactory` already uses) and the bridged claude.ai cookies.
Decode with `UsageAPIModels` (Task 1) and map with `UsageMapper` (Task 2).

Classification (Data Models §"Classification order matters") is the subtle part:
a 200 whose body is actually the login page must resolve to `.notLoggedIn` — NOT
`.decodeFailed` — and that check must happen BEFORE JSON decode, because
`.notLoggedIn` triggers the Decision 7 backoff while `.decodeFailed` would trigger
the expensive DOM-scrape fallback.

SECURITY (Decision 6): cookie values (`sessionKey`, `cf_clearance`, `__cf_bm`) and
request headers are NEVER logged. Log only value-free events (status code, result
case, org-discovery outcome). Any token-adjacent field that must be logged uses
`privacy: .private`. Do not copy the existing `privacy: .public` pattern onto
anything cookie- or header-related.

This task DEPENDS ON Tasks 1-4 — reuse `UsageAPIModels`, `UsageMapper`,
`OrgIDStore`, `CookieBridge`. Do NOT redefine those types.

## What to do

- Create `App/Sources/ClaudeCounter/Scraper/UsageAPIClient.swift`.
- Define the `UsageFetchResult` enum exactly as in tech-spec Data Models:
  `success(ClaudeUsage)`, `needsCookieRefresh`, `notLoggedIn`, `decodeFailed`,
  `transport(Error)`. (Confirm whether Task 1/2 already declared it; if so, reuse —
  do not duplicate. Otherwise declare it here.)
- Build the client around an injectable `URLSessionConfiguration` so tests can
  register a stub `URLProtocol`. The default production config sets the no-cookie-jar
  triplet (`httpCookieStorage = nil`, `httpCookieAcceptPolicy = .never`,
  `httpShouldSetCookies = false`).
- Implement an off-host redirect delegate (`URLSessionTaskDelegate`
  `willPerformHTTPRedirection`): if the redirect target host is not `claude.ai`,
  return a new request with the `Cookie` header removed; otherwise allow it.
- Implement `fetch()` returning `UsageFetchResult`:
  - Resolve org uuid: read `OrgIDStore`; on miss `GET /api/organizations`, decode
    via `OrgSummary`, pick the active/first uuid, cache it. Invalidate the cache on
    auth/not-found failures so the next tick re-discovers.
  - `GET /api/organizations/{uuid}/usage` with the Safari UA and bridged cookies.
  - Classify the response (see classification rules below) BEFORE attempting decode
    where required; on a decodable 200, decode + map and return `.success` or
    `.decodeFailed`.
  - Wire in `CookieBridge` for cookie read on the outgoing request and `Set-Cookie`
    write-back on success (CookieBridge owns the read/write-back mechanics; this
    client just calls it).
- Reuse the Safari UA: extract or expose `WebViewFactory.safariUserAgent` so there
  is ONE UA string. Do not hand-copy the literal — share the source.
- Apply Decision 6 logging discipline throughout.
- Write the unit/integration tests in `App/Tests/ClaudeCounterTests/` (see TDD
  Anchor), stubbing the network via `URLProtocol` injected through the config.

## TDD Anchor

Тесты пишем ДО реализации (URLProtocol-stubbed, path-routed `/organizations` →
`/usage`). Each test injects a `URLSessionConfiguration` whose `protocolClasses`
contains a stub that routes by request path. Degenerate bodies (Cloudflare
"Just a moment…" HTML, login-page HTML, garbage JSON) are pinned as small inline
string fixtures so classification is deterministic.

- `App/Tests/ClaudeCounterTests/UsageAPIClientTests.swift::testSuccessReturnsPopulatedUsage`
  — stub `/organizations` → single-org fixture, `/usage` → `usage.json` fixture;
  `fetch()` returns `.success` with a populated `ClaudeUsage` (current %, weekly %,
  both reset Dates) matching the fixture.
- `…::testChallengeHTMLReturnsNeedsCookieRefresh` — `/usage` → HTTP 403 +
  "Just a moment…" challenge HTML → `.needsCookieRefresh`.
- `…::testLoginPageBodyReturnsNotLoggedIn` — `/usage` → HTTP 200 whose body is the
  login-page HTML → `.notLoggedIn` (NOT `.decodeFailed`; classified before decode).
- `…::test401ReturnsNotLoggedIn` — `/usage` → 401 (and a separate case: redirect to
  `/login`) → `.notLoggedIn`.
- `…::testGarbageJSONReturnsDecodeFailed` — `/usage` → HTTP 200 with valid-but-
  unmappable JSON → `.decodeFailed`.
- `…::testDiscoveryCachesUUID` — first `fetch()` hits `/organizations` and writes the
  uuid into an isolated `OrgIDStore` (use `UserDefaults(suiteName:)`, not
  `.standard`); a second `fetch()` does NOT re-request `/organizations`.
- `…::testMultiOrgPicksActiveOrFirst` — `/organizations` → two-org fixture →
  active/first uuid chosen and cached.
- `…::testTransportErrorReturnsTransport` — stub raises a `URLError` → `.transport`.
- `…::testOffHostRedirectStripsCookie` — redirect to a non-claude.ai host → outgoing
  request to that host carries no `Cookie` header.
- `…::testNoCookieValueInLogs` — drive a fetch through a captured log sink with a
  sentinel cookie value; assert the sentinel never appears in any emitted log line
  (header or body) (Decision 6).

## Acceptance Criteria

- [ ] `fetch()` returns a populated `ClaudeUsage` over `URLSession` with no cookie jar
      of its own — host-scoped cookies (`httpCookieStorage = nil`, `httpCookieAcceptPolicy
      = .never`, `httpShouldSetCookies = false`) and off-host redirects strip the `Cookie`
      header so cookies only ever reach claude.ai (Decision 2).
- [ ] The org uuid is discovered via `/api/organizations` and cached via `OrgIDStore`
      (single-org and multi-org → active/first), and not re-requested on the next fetch.
- [ ] All outcomes are classified correctly — `.success` / `.needsCookieRefresh`
      (403+challenge) / `.notLoggedIn` (401, `/login` redirect, 200-login-HTML body) /
      `.decodeFailed` / `.transport` — and no cookie or header is ever logged (Decision 6).

  must have been logged in at least once on this machine.

## Details

**Files:**
- `App/Sources/ClaudeCounter/Scraper/UsageAPIClient.swift` (new) — the client, its
  `URLSessionConfiguration` factory, the off-host redirect delegate, `fetch()`, and
  (if not already provided by Task 1/2) the `UsageFetchResult` enum.
- `App/Sources/ClaudeCounter/Scraper/WebViewFactory.swift` — currently the Safari UA
  is `private static let safariUserAgent` (lines ~54-58). Expose it (e.g.
  `static let safariUserAgent` / a shared constant) so the client reuses the same
  string instead of copying the literal.
- `App/Tests/ClaudeCounterTests/UsageAPIClientTests.swift` (new) — the TDD-Anchor
  tests with a stub `URLProtocol`.

**Endpoints / shape (from fixtures):**
- `GET https://claude.ai/api/organizations` → JSON array of orgs; each has `uuid`
  (e.g. `00000000-0000-4000-8000-000000000001`). Single-org in the committed fixture;
  add a two-org variant for `testMultiOrgPicksActiveOrFirst`.
- `GET https://claude.ai/api/organizations/{uuid}/usage` → `usage.json`: a `limits[]`
  array with `kind` of `session` / `weekly_all` / `weekly_scoped`, `percent`,
  `resets_at` (ISO-8601 + fractional seconds + `+00:00`), plus flat `five_hour` /
  `seven_day` fallback fields. Mapping is Task 2's job — call `UsageMapper`.

**Dependencies:**
- Tasks 1 (`UsageAPIModels`), 2 (`UsageMapper`), 3 (`OrgIDStore`), 4 (`CookieBridge`)
  must exist. Reuse their public types; do not redefine `UsageFetchResult`,
  `OrgSummary`, `UsageResponse`, `UsageLimit`, `ClaudeUsage`.
- No new external packages (Foundation + WebKit only).

**Edge cases:**
- 200 response whose body is the login HTML → `.notLoggedIn`, classified BEFORE JSON
  decode (Decision 7 backoff vs. expensive DOM fallback hinges on this).
- 403 with Cloudflare "Just a moment…" challenge HTML → `.needsCookieRefresh`.
- 401, or a redirect to `/login` → `.notLoggedIn`.
- 200 valid-but-unmappable JSON → `.decodeFailed`.
- Org discovery returns an empty array or a 401 → invalidate cache, surface
  `.notLoggedIn`/`.decodeFailed` appropriately; do not crash.
- Redirect that leaves `claude.ai` → strip `Cookie` header.
- `WKHTTPCookieStore` is async / MainActor (per Risks): CookieBridge fetches cookies
  on MainActor before the request is built; the network fetch itself runs off-main.

**Implementation hints (NOT pseudocode):**
- Detect the login page by a content-type that is `text/html` and/or a stable
  login-page marker string; detect the challenge by a 403 + "Just a moment" marker.
  Keep these checks ahead of any `JSONDecoder` call.
- The redirect delegate goes on the `URLSession` you create from the injected config;
  the same delegate path must run under the stub `URLProtocol` so the
  `testOffHostRedirectStripsCookie` test exercises real logic.
- Decode the org list with `OrgSummary` (Task 1); for "active" selection rely on the
  fixture/field semantics (active flag if present, else first). Cache via `OrgIDStore`.
- For the log-guard test, route `AppLog`-style output through an injectable sink or
  assert on captured `OSLogStore`/string output; never assert by logging the cookie.
