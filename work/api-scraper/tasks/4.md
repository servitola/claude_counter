# Task 4: CookieBridge (read + write-back, host-scoped)

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

`CookieBridge` is the single seam between the WebView's cookie store and the
new URLSession-based API client (Task 5). The login window and the WebView
fallback both persist claude.ai cookies (`sessionKey`, `cf_clearance`,
`__cf_bm`, …) into `WKWebsiteDataStore.default().httpCookieStore`. Per
Decision 2, that store is the **single source of truth** — the API session
keeps no cookie jar of its own and re-reads cookies through this bridge before
every fetch.

This task delivers two directions of flow:

1. **Read (out):** pull cookies from the WebView store, keep **only** those
   scoped to `claude.ai`, and hand them to the caller as `[HTTPCookie]` (plus,
   for convenience, the `Cookie` request-header value). Cookies for any other
   host are never returned, so they can never be attached to an outgoing
   request.
2. **Write-back (in):** take `Set-Cookie` headers from a successful API
   response and write the resulting cookies **back into the same WebView
   store**, so rotating cookies (`__cf_bm` ~every 30 min, a refreshed
   `sessionKey`) keep the store fresh and the expensive WebView fallback fires
   less often.

`WKHTTPCookieStore` is async and MainActor-bound. The read must complete on
MainActor and produce a plain `[HTTPCookie]` value *before* the (off-main)
request is built, so the fetch itself never touches WebKit (mitigates the
"cookie read race" risk in the tech-spec). This is a security-sensitive
component: per Decision 6, **no cookie name or value is ever logged** — only
counts and host may appear, and any token-adjacent field uses
`privacy: .private`.

## What to do

- Add `App/Sources/ClaudeCounter/Scraper/CookieBridge.swift` with a
  `CookieBridge` type that accesses
  `WKWebsiteDataStore.default().httpCookieStore`.
- Provide a MainActor read API that returns all `claude.ai`-scoped cookies as
  a value type (`[HTTPCookie]`), filtering out every cookie whose domain does
  not match `claude.ai` (handle the leading-dot form `.claude.ai` and the bare
  host). Cookies for unrelated hosts must not be in the result.
- Provide a helper that turns `[HTTPCookie]` into the `Cookie` request-header
  string (name=value pairs joined by `; `) for callers that want the header
  form. The caller (Task 5) decides whether to use `[HTTPCookie]` directly or
  the header string.
- Provide a MainActor write-back API that accepts the `Set-Cookie` header
  field(s) plus the response URL, parses them into `HTTPCookie` objects scoped
  to `claude.ai`, and inserts each into the store via `setCookie`. Skip any
  parsed cookie that is not `claude.ai`-scoped.
- Use only real WebKit/Foundation APIs: `httpCookieStore`, `getAllCookies`,
  `setCookie`, `HTTPCookie.cookies(withResponseHeaderFields:for:)` /
  `HTTPCookie.requestHeaderFields(with:)`.
- Make the store injectable (default `WKWebsiteDataStore.default()`) so tests
  can supply an isolated store seeded with cookies.
- Logging: if anything is logged at all, log only counts and/or host via
  `AppLog.scraper`; never a cookie name or value. Use `privacy: .private` on
  any field that could carry token-adjacent data.
- Make the log output **capturable by a test**: route emitted log strings
  through a small injectable logging closure (or the existing `AppLog`
  wrapper) so the Decision-6 guard test can collect every emitted line and
  assert a sentinel cookie value/name never appears. Provide the seam — leave
  the exact mechanism to the implementer.

**Files:**
- `App/Sources/ClaudeCounter/Scraper/CookieBridge.swift` (new) — the bridge
  type. Read API (MainActor) → `[HTTPCookie]` + `Cookie` header helper;
  write-back API (MainActor) accepting `Set-Cookie` header fields + URL.
  Injectable store, default `WKWebsiteDataStore.default()`.

**Dependencies:** none (Wave 1, `depends_on: []`). Consumed by Task 5
(`UsageAPIClient`), which wires the read into request building and the
write-back into response handling. Keep the public surface small and
value-oriented so Task 5 can call it without WebKit knowledge.

> Note: Promoted from tech-spec Wave 2 to Wave 1 — `CookieBridge` has no
> dependency on Tasks 1–3; it reads only WebKit cookie APIs
> (`WKWebsiteDataStore` / `httpCookieStore`). Intentional decomposition
> refinement, hence `wave: 1` / `depends_on: []`.

**Edge cases:**
- Cookie domain may be stored with a leading dot (`.claude.ai`) or as the bare
  host — match both; do NOT match suspicious lookalikes (`notclaude.ai`,
  `claude.ai.evil.com`).
- Empty store → read returns `[]` and an empty header string; caller must
  tolerate, do not crash.
- Malformed / unparseable `Set-Cookie` → skip that entry, keep the rest.
- Write-back of a non-claude cookie (defense in depth) → skip it.
- `WKHTTPCookieStore` is async — `await getAllCookies` on MainActor and return
  a captured value; never call WebKit from the off-main request build.

**Implementation hints:**
- `AppLog` call sites elsewhere use `privacy: .public`; do NOT copy that for
  anything cookie-related. Prefer a count-only line like
  `AppLog.scraper.debug("cookie read host-scoped count=\(n, privacy: .public)")`
  with no names/values, or omit logging entirely.
- `HTTPCookie.cookies(withResponseHeaderFields:for:)` builds cookies from a
  `Set-Cookie` dictionary keyed by `"Set-Cookie"`;
  `HTTPCookie.requestHeaderFields(with:)` produces the `Cookie` header — or
  assemble `name=value; …` directly if you want explicit control.
- Make the store an init parameter so tests can pass an isolated
  `WKWebsiteDataStore.nonPersistent()` and seed cookies via `setCookie`.
- Likewise make the log output reachable by tests: an injectable logging
  closure (default → `AppLog.scraper`) lets the secret-log guard test capture
  emitted strings and assert no sentinel cookie value/name leaks. Keep the
  default path logging counts/host only.
